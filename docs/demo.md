# 使用示例

下面以耳机对比为例，介绍如何创建任务、查看运行过程，以及处理报告中的问题。

## 1. 创建任务

点击“发起任务”，填入研究目的和具体型号，例如对比 AirPods Pro 2（USB-C 充电盒版本）与 Sony WF-1000XM5，供使用 iPhone 的通勤用户参考。

比较维度可以设为兼容功能、开启降噪时的续航、防水等级，以及销售渠道的价格和保修条件。不同测试条件不能直接比较，历史售价也不能当作当前价格。

## 2. 开始研究

保存任务后，在“研究计划”的输出区域点击“发起研究运行”。实时运行需要先完成[连接配置](setup.md)，并会消耗模型和搜索服务的额度。

执行期间可以查看每一步的状态。遇到搜索或读取异常时，系统会保留记录，并在允许的范围内继续处理。不要重复点击执行，以免重复调用。

## 3. 查看资料和报告

在“网页读取”中查看来源链接、获取时间和正文是否被截断。报告中的结论可以与提取的事实及原文对照检查。

耳机案例中，系统发现草稿把模型对旧兼容列表的解释写成了索尼官方声明，因此将报告标为待复核。没有采集到的续航或当前价格也会保留为缺失信息，而不是自动补上。

## 4. 记录意见并复测

在“结论复核”中保存意见。如果需要补充资料，可以复制任务，修改输入后重新运行，再通过版本对比查看变化。人工意见不会覆盖原始模型结果。

## 查看已有运行

没有配置 API 时，也可以导入 `examples/case-2.json` 查看耳机案例的脱敏摘要。其他样本分别对应软件选型与食品比较。

这些文件来自真实运行，但省略了完整事实和网页正文，不是实时执行结果，也不能替代完整证据检查。
